# Enterprise E-Commerce Platform — Project Specification

You are the lead architect and senior full-stack engineer responsible for designing and developing an enterprise-grade e-commerce platform similar in overall capability to Amazon / Flipkart.

The application must be designed for:

* High scalability
* High availability
* Security
* Maintainability
* Multi-vendor readiness
* Large product catalogs
* High concurrent traffic
* Mobile-first user experience
* AWS cloud deployment
* Production use
* Google Play Store deployment
* Apple App Store deployment

Do NOT attempt to build the entire application at once.

We will develop this project in clearly defined phases. Each phase must be reviewed and approved before moving to the next phase.

---

# 1. Technology Stack

## Mobile Frontend

Use:

* React Native
* TypeScript
* Expo
* React Navigation / Expo Router where appropriate
* React Query / TanStack Query for server state
* Zustand or an equivalent lightweight state-management solution
* Form validation using Zod or an appropriate equivalent
* Secure token storage using platform-appropriate secure storage
* Responsive UI suitable for Android and iOS
* Push notifications
* Deep linking
* App version/update handling
* Production-ready error handling
* Analytics-ready architecture

The application must be compatible with:

* Android
* iOS
* Google Play Store
* Apple App Store

Do not use web-only React components or browser-specific APIs unless there is a clear mobile-compatible alternative.

---

# 2. Backend

Use:

* Python
* FastAPI
* Pydantic
* SQLAlchemy 2.x
* Alembic
* PostgreSQL
* Redis where required
* Celery / background processing mechanism where appropriate

Backend requirements:

* REST API architecture
* Versioned APIs
* `/api/v1/...` style API structure
* Authentication and authorization
* Role-based access control
* Request validation
* Centralized exception handling
* Structured logging
* Audit logging
* Pagination
* Filtering
* Sorting
* Search
* Rate limiting where required
* Idempotency for important transactional APIs
* Transaction management
* Database migrations
* Secure password handling
* JWT/access-token architecture
* Refresh-token architecture
* API documentation using OpenAPI/Swagger
* Health-check endpoints
* Readiness/liveness endpoints
* Production-ready configuration management

Design the backend so that it can later evolve into independently scalable services if required.

Do not introduce microservices unnecessarily during the first implementation. Start with a well-structured modular monolith unless there is a strong architectural reason otherwise.

---

# 3. Database

Use:

* PostgreSQL

The database must be designed as an enterprise-grade relational model.

Important principles:

* Proper normalization
* Appropriate denormalization only when justified
* UUID primary keys where appropriate
* Foreign-key relationships
* Unique constraints
* Check constraints
* Indexes
* Composite indexes
* Audit columns
* Soft-delete strategy where appropriate
* Created/updated timestamps
* Status fields using controlled values
* Transaction-safe financial/order operations
* Proper monetary data types
* No floating-point values for money
* Referential integrity
* Avoid unnecessary duplication
* Avoid JSON columns when a normalized relational structure is more appropriate

All important database design decisions must be documented.

# 24. Important Development Rules

1. Do not skip the database review gate.
2. Do not start frontend development before database approval.
3. Do not start complex backend implementation before the database design is approved.
4. Do not make major architectural decisions silently.
5. If requirements are ambiguous, document the assumption.
6. Prefer simple scalable architecture over unnecessary microservices.
7. Do not introduce unnecessary AWS services.
8. Do not hard-code secrets.
9. Do not copy proprietary Amazon/Flipkart assets or branding.
10. Keep the application production-ready from the beginning.
11. Write tests alongside important business logic.
12. Keep database migrations version controlled.
13. Maintain backward compatibility for APIs where practical.
14. Treat order/payment/inventory operations as critical transactional workflows.
15. Never assume a payment was successful based only on a client-side response.
16. Verify payment status server-side.
17. Design webhook processing to be idempotent.
18. Protect inventory from overselling through proper transaction/concurrency controls.
19. Preserve historical order information through snapshots.
20. Before implementing a new feature, check whether the database, API, backend service, and mobile architecture support it cleanly.
